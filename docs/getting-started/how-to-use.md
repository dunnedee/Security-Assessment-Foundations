# How to use this resource

## A suggested path

You can read in any order, but if you're new, this sequence builds naturally:

1. **[Assessment management](../assessment-management/index.md)** — start with
   the professional frame: the law, scoping, risk, and reporting. This is what
   separates a professional from someone who merely knows some tools.
2. **[Core technical skills](../core-technical/index.md)** — protocols,
   cryptography, and password storage. The foundations everything else rests
   on.
3. **[Information gathering](../information-gathering/index.md)** — how targets
   and organisations expose information, and how that's reduced.
4. **[Networking & infrastructure](../networking-infrastructure/index.md)** —
   mapping networks, enumerating services, and wireless.
5. **[Vulnerability assessment](../vulnerability-assessment/index.md)** —
   finding and validating weaknesses.
6. **[Web & databases](../web-and-databases/index.md)** — the application layer
   and the data behind it.
7. **[Exploitation concepts](../exploitation-concepts/index.md)** — how it all
   comes together, conceptually, with defence front and centre.

## How to actually learn it

Reading is the smallest part. The knowledge sticks when you do three things:

=== "Read actively"

    Don't just absorb — interrogate. For every weakness, ask yourself: *Why
    does this exist? What decision or default created it? How would I spot it?
    How would I stop it?* The **Check your understanding** prompts at the end
    of each page are there to force this.

=== "Practise safely"

    Stand up a [home lab](home-lab.md) and reproduce the concepts on systems
    you own. There is no substitute for seeing a thing with your own eyes in an
    environment where you can't hurt anyone.

=== "Explain it back"

    If you can explain a concept simply — to a peer, in a blog post, in a study
    group — you understand it. If you can't, you've found your next gap.

## Good companion resources

This resource is deliberately conceptual. Pair it with hands-on platforms and
primary sources:

- **[TryHackMe](https://tryhackme.com/)** — guided, beginner-friendly practical
  rooms.
- **[Hack The Box Academy](https://academy.hackthebox.com/)** — structured
  modules with hands-on labs.
- **[OWASP](https://owasp.org/)** — the authoritative source on web application
  security, including the Top 10 and testing guides.
- **[PortSwigger Web Security Academy](https://portswigger.net/web-security)** —
  free, excellent, hands-on web security labs.
- **Vendor and project documentation** — the real manual for any tool is always
  better than someone's summary of it.

!!! info "Why no answer keys here?"
    The **Check your understanding** prompts are open questions on purpose. The
    point is to send you back into the material (or your lab) to work out the
    answer, which is how it sticks. It also keeps this resource firmly on the
    right side of being study material rather than an exam crib.
